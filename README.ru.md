# blackpane

[English](README.md)

Выключает и включает встроенный экран MacBook при открытой крышке — как штора блэкаут
на окне: окно на месте, свет не проходит. Удобно, когда работаешь на внешнем мониторе,
а крышку закрывать не хочется: Touch ID остаётся под рукой, встроенный экран — тёмным.

- **Одиночное нажатие правого Option** — выключить встроенный экран, ещё одно — включить.
- **Внешних мониторов не осталось** (отключили кабель, в том числе во сне при закрытой
  крышке) — встроенный включается сам.
- **Без внешнего монитора** выключить встроенный экран нельзя.

Разрабатывалось и тестировалось на MacBook Pro 16″ (M1 Pro) с macOS 27.0.1 (26A434).

```text
src/blackpane.m                        программа
launchd/extdesign.blackpane.plist.in   шаблон агента launchd
Makefile                               сборка, установка, удаление
build/                                 результат сборки (не в git)
```

## Установка

1. Поставить Xcode Command Line Tools, если их ещё нет:

   ```bash
   xcode-select --install
   ```

2. Скачать исходники:

   ```bash
   git clone https://github.com/extdesign/blackpane.git
   cd blackpane
   ```

3. Собрать и установить. Отдельно собирать не нужно: `make install` сначала
   компилирует программу в `build/` (и пересобирает её, если изменились исходник или
   `VERSION`), потом ставит. `make` без параметров только собирает.

   ```bash
   make install
   ```

   Что ставится:

   | Что | Куда |
   |---|---|
   | программа | `~/.local/bin/blackpane` |
   | агент launchd (запускается при входе, перезапускается, если вышел) | `~/Library/LaunchAgents/extdesign.blackpane.plist` |

   Агент запускается сразу, а дальше — при каждом входе: launchd при входе читает
   агентов из вашей `~/Library/LaunchAgents` и запускает те, у которых `RunAtLoad`.
   Работает только у вашего пользователя. Повторный `make install` после изменений
   перезаписывает оба файла и перезапускает агента — ничего не копится.

4. Выдать разрешение **«Мониторинг ввода»**. Сразу после запуска macOS показывает
   запрос для `blackpane`; из него перейти в «Системные настройки → Конфиденциальность
   и безопасность → Мониторинг ввода» и включить `blackpane`. Если запроса не было —
   открыть этот раздел самому: `blackpane` уже в списке, выключен. Если его там нет —
   нажать «+» и выбрать `~/.local/bin/blackpane` (папка `.local` скрытая: в окне выбора
   `Cmd+Shift+.`).

   Перезапускать ничего не нужно: наблюдатель подхватит разрешение за 10–20 секунд
   (почему так — в «Неполадках с разрешением»).

5. Проверить: одиночное нажатие правого Option выключает встроенный экран, ещё одно —
   включает. В журнале — `watching the right Option key`:

   ```bash
   tail ~/Library/Logs/blackpane.log
   ```

Без разрешения не работает только клавиша; возврат экрана при отключении монитора
работает.

## Неполадки с разрешением

Что встречалось при разработке и как это лечится:

| Что видно | Почему | Что делать |
|---|---|---|
| Разрешение выдано, а клавиша не работает | macOS запоминает ответ о разрешении на всё время жизни процесса; наблюдатель, запущенный без разрешения, его не видит | подождать 10–20 секунд — без разрешения наблюдатель каждые 10 секунд выходит, и launchd запускает его заново; или перезапустить сразу: `launchctl kickstart -k gui/$(id -u)/extdesign.blackpane` |
| Настройки пишут, что приложение будет перезапущено, но ничего не меняется | это касается приложений, а наблюдатель — агент launchd | как выше |
| После пересборки (`make install`) клавиша перестала работать, переключатель включён | подпись у программы локальная; пересборка — новая программа для macOS, старое разрешение к ней не подходит | удалить `blackpane` кнопкой «−» и добавить `~/.local/bin/blackpane` через «+» (выключить и включить переключатель недостаточно); чтобы так не было — «Если часто пересобираете» |
| В журнале `no Input Monitoring permission — restarting every 10 s until granted` | разрешения нет (или после пересборки оно не подходит); строка пишется один раз, следующие перезапуски молчат | выдать, как в шаге 4; в журнале появится `Input Monitoring permission granted` |
| В журнале `watching the right Option key`, а клавиша не работает | перехват, созданный до выдачи разрешения, событий не получает | `launchctl kickstart -k gui/$(id -u)/extdesign.blackpane` |
| На экране блокировки клавиша не работает | пока экран заблокирован, macOS не отдаёт нажатия программам | так задумано; отключение монитора экран всё равно вернёт |
| Разрешение выключили, а следующее нажатие… | macOS продолжает доставлять нажатия в перехват, созданный, пока разрешение было | с 0.6.1 каждое нажатие проверяется свежим процессом: первое нажатие после снятия разрешения экран не переключает, в журнале — `Input Monitoring permission revoked — key ignored, restarting`; если встроенный экран был выключен, он включается (клавиша больше не работает), и наблюдатель перезапускается уже без разрешения |

## Если часто пересобираете: сохранить разрешение

При обычной установке не нужно — пропустите, если обновляете blackpane изредка.

По умолчанию программа подписана локально («ad hoc»). Тогда macOS привязывает
разрешение «Мониторинг ввода» к конкретной сборке, и после каждой пересборки его надо
выдавать заново. Программы из App Store и от разработчиков сохраняют разрешения при
обновлениях, потому что подписаны сертификатом: macOS запоминает «этот идентификатор
от этого сертификата». blackpane может так же — с сертификатом, который вы сделаете
сами, бесплатно:

```bash
make cert
```

Команда создаёт самоподписанный сертификат для подписи кода `blackpane-signing` на 10 лет
в вашей связке ключей «вход» и один раз спрашивает пароль от входа в систему — чтобы
доверять ему для подписи кода. Дальше `make install` подписывает им сам (сборка пишет
`signed with: blackpane-signing`). Разрешение выдать последний раз («−», потом «+», как
после любой пересборки); следующие пересборки его сохранят. Если `make cert` прервали
(например, закрыли окно с паролем), запустите ещё раз: уже импортированному сертификату
будет выставлено доверие.

Сертификат нужен только для подписи blackpane на этом Маке. Убрать его:

```bash
make cert-remove
```

Следующая сборка снова будет с локальной подписью. Можно подписать и любым другим своим
сертификатом для подписи кода: `make install SIGN="имя сертификата"` — программа будет
переподписана, даже если больше ничего не менялось. Переменная `SIGN` из окружения не
учитывается, только заданная в команде `make`.

## Удаление

В папке проекта:

```bash
make uninstall
```

Останавливает агента (наблюдатель, выходя, включает встроенный экран), на всякий случай
выполняет `blackpane light` и убирает всё, что blackpane оставляет:

| Что | Где |
|---|---|
| агент launchd | `~/Library/LaunchAgents/extdesign.blackpane.plist` |
| программа | `~/.local/bin/blackpane` |
| сохранённый номер встроенного экрана | `~/Library/Application Support/blackpane/` |
| отметка «нет разрешения» | `blackpane.no-access` в `getconf DARWIN_USER_TEMP_DIR` |

Журнал `~/Library/Logs/blackpane.log` остаётся — для разбора; если не нужен, удалить
вручную.

**Разрешение «Мониторинг ввода» убирается вручную:** «Системные настройки →
Конфиденциальность и безопасность → Мониторинг ввода» → выбрать `blackpane` → «−».
Командой это не сделать: `tccutil reset ListenEvent <id>` принимает только приложения,
известные LaunchServices, и для консольной программы отвечает `No such bundle identifier
… (OSStatus error -10814)` — подписана она сертификатом или нет, — а `tccutil reset ListenEvent` без идентификатора сбросил бы
разрешение у всех программ.

`make clean` убирает папку сборки.

## Команды

```text
blackpane toggle    dark, если горит; light, если погашен
blackpane dark      погасить встроенный экран — только если есть внешний монитор
blackpane light     включить встроенный экран
blackpane status    какие мониторы видит macOS
blackpane version   версия
blackpane access    выдан ли «Мониторинг ввода» (код выхода 0 — да)
blackpane watch     наблюдатель; запускает агент launchd
```

`blackpane access`, запущенный из терминала, показывает разрешение терминала, а не
blackpane: macOS проверяет программу, из которой запустили. Наблюдатель запускает его
для себя.

## Журнал

`~/Library/Logs/blackpane.log` — обычный текстовый файл. В программе «Консоль» он в
«Отчётах журналов» как `blackpane.log`, со всей историей; в терминале — `tail` или `less`.

Что пишется: запуск и остановка наблюдателя, каждое `dark`/`light` (от клавиши,
наблюдателя или из командной строки) с результатом, отказы, проверки мониторов со
списком активных, состояние разрешения. Ошибки — с ненулевым `err=`. В каждой строке
версия и номер процесса:

```text
2026-10-25 00:42:10 [0.8.2 4512] watcher 0.8.2 started err=0
2026-10-25 00:42:10 [0.8.2 4512] watching the right Option key err=0
2026-10-25 00:42:31 [0.8.2 4512] dark (key) id=1 err=0
2026-10-25 00:42:33 [0.8.2 4512] check: 1 online — 3:3840x1600:vendor=0x1e6d
2026-10-25 00:45:02 [0.8.2 4517] light (cli) id=1 err=0
```

`(key)` — правый Option, `(cli)` — командная строка. Строка `check` перечисляет
подключённые мониторы, по которым принято решение; `:inactive` — подключён, но не
показывает (аппаратное зеркалирование), `:virtual` — заглушка, которую macOS заводит,
когда мониторов не осталось, а `lid closed` добавляется, когда крышка закрыта.

Это несколько строк в день, поэтому файл не делится на части — мегабайт набирается
годами. Наблюдатель без разрешения перезапускается каждые 10 секунд, но пишет об этом
один раз.

## Важно

Сам по себе выключенный встроенный экран остаётся выключенным после блокировки, сна и
выхода из учётной записи — сбрасывает это только перезагрузка. Возвращает его
наблюдатель:

- **Внешнего монитора не стало** — наблюдатель включает встроенный экран.
- **Наблюдатель останавливают** (выход из учётной записи, `launchctl bootout`,
  `make install`, `make uninstall`, `kill` сигналами SIGTERM, SIGINT, SIGHUP, SIGQUIT) —
  перед выходом он включает встроенный экран, и окно входа появится и на нём.
- **Наблюдатель убит `kill -9` или упал** — это не поймать. launchd запускает его заново
  (`KeepAlive` перезапускает после любого нештатного выхода), и при старте он включает
  встроенный экран, если внешнего монитора нет.

Наблюдатель с разрешением ничего не опрашивает и не перезапускается; launchd запускает
его заново только после падения, `kill -9` или выхода «нет разрешения».

Остаётся один случай: агент удалён насовсем (plist стёрт вручную, без `make uninstall`),
экран выключен, и внешний монитор отключили. Тогда Мак без экрана — перезагрузка: после
неё экран включается всегда.

## Клавиша

Наблюдатель слушает клавиши, кнопки мыши и прокрутку и ничего в них не меняет.

- Правый Option отличается от левого по коду клавиши (61) и флагу `NX_DEVICERALTKEYMASK`.
- Срабатывает только **одиночное короткое** нажатие. Экран не трогается, если правый
  Option нажат вместе с другой клавишей, щелчком или прокруткой мыши (Option-щелчок) или
  при уже зажатом другом модификаторе (Command, Shift, Control, Fn, левый Option); если
  его держали дольше 0,5 с; и при двойном нажатии — второе нажатие начато в пределах
  0,35 с после первого отпускания. Двойное остаётся другим программам, которые на него
  откликаются.
- Поэтому экран переключается через 0,35 с после нажатия: наблюдатель ждёт, не начнётся
  ли второе; как только оно начинается, ожидающее переключение отменяется.
- Пока экран заблокирован, macOS не отдаёт нажатия программам — клавиша не работает.
- При закрытой крышке клавиша ничего не делает: встроенного экрана тогда нет в списке,
  как будто он погашен, и переключать нечего. `blackpane light` при закрытой крышке
  работает — экран загорится, когда крышку откроют.

## Как устроено

Экран отключается закрытым вызовом `CGSConfigureDisplayEnabled` (SkyLight, доступен через
CoreGraphics) в транзакции `CGBeginDisplayConfiguration` … `CGCompleteDisplayConfiguration`
с `kCGConfigureForSession`. Транзакция повторяет стандартную схему Apple для настройки
дисплеев (начать, изменить, завершить, при ошибке отменить); закрытый только сам вызов
изменения. Закрытый API может сломаться в новой macOS — тогда `dark` вернёт ошибку, а
экран останется включённым.

Выключенный экран пропадает из списка мониторов, поэтому его номер запоминается в файле
`~/Library/Application Support/blackpane/builtin-id` — не во временной папке: оттуда
macOS удаляет файлы, к которым не обращались несколько дней, а экран может быть погашен
и дольше. Файла нет — наблюдатель берёт 1: так нумеруется встроенный экран на Apple
Silicon; `blackpane light` вместо догадки сообщает, что номер неизвестен.

При закрытой крышке встроенного экрана в списке тоже нет. blackpane различает эти случаи
по состоянию крышки (`AppleClamshellState` у `IOPMrootDomain`).

Наблюдатель (`watch`) — процесс без окон, иконки в Dock и меню. Спит в ожидании событий
и процессор не тратит. Память — около 9–10 МБ физически (`footprint <pid>`); `ps`
показывает около 35 МБ RSS, большая часть — общие системные библиотеки.

## Что выяснили проверками

Без наблюдателя:

| Что сделали при выключенном встроенном экране | Встроенный экран |
|---|---|
| `dark` — процесс завершился | остался выключен: держать процесс не нужно |
| `light` отдельным запуском | включился |
| Блокировка экрана, сон, погашенные дисплеи | остался выключен |
| Закрыли крышку при подключённом мониторе | ничего не мигнуло: переключаться не на что |
| Отключили монитор (при открытой и закрытой крышке) | **остался выключен** — Мак без экрана |
| Выход из учётной записи | **остался выключен**, окно входа — только на внешнем |
| Перезагрузка | включился |

`kCGConfigureForSession` действует до конца сеанса WindowServer, а он живёт до
перезагрузки: выход из учётной записи экран не возвращает. Отсюда наблюдатель.

С наблюдателем после отключения монитора встроенный экран включается примерно за две
секунды, а при закрытой крышке — ещё до того, как Мак уснёт.

Что оказалось неочевидным:

- **Наблюдатель — `NSApplication`.** События `CGDisplayRegisterReconfigurationCallback`
  WindowServer присылает только процессу, зарегистрированному как приложение: консольная
  программа с `CFRunLoopRun` их не получает.
- **Виртуальный монитор не в счёт.** Когда мониторов не остаётся, macOS заводит
  виртуальный — 1×1 или 1920×1080, производитель `0x756e6b6e` (`unkn`). У настоящего есть
  сервис IOKit (`CGDisplayIOServicePort`) или 16-битный номер производителя.
- **Клавиша ловится напрямую, без переназначения.** Вариант «`hidutil` превращает правый
  Option в F19, F19 регистрируется `RegisterEventHotKey`» разрешения не требует, но у
  `hidutil` один список переназначений на всю систему и `--set` заменяет его целиком
  (сломает другие переназначения), F-клавиша на другом Маке может быть занята, а
  переназначенный Option перестаёт быть Option для других программ.
- **Ответ о разрешении кешируется в процессе.** Без «Мониторинга ввода» перехват клавиш
  создаётся, но события в него не приходят — и после выдачи разрешения тоже: macOS
  запоминает ответ на всё время жизни процесса. Поэтому без разрешения наблюдатель через
  10 секунд выходит с кодом ошибки, а launchd запускает его заново; штатный выход
  (код 0, например при выходе из учётной записи) не перезапускается.
- **launchd держит plist в памяти.** `launchctl kickstart` перезапускает агента со
  старыми аргументами; изменённый plist подхватывается только через `bootout` и
  `bootstrap`. `bootout` возвращается раньше, чем агент выгружен, — `make install` ждёт,
  иначе `bootstrap` падает с «5: Input/output error».

## Аналоги

То же умеют [BetterDisplay](https://github.com/waydabber/BetterDisplay) и
[blackoutd](https://github.com/toobuntu/blackoutd), на том же закрытом вызове. Оба намного
больше: у BetterDisplay отключение экрана — часть большого платного набора (в бесплатной
версии его нет), у blackoutd вокруг него около 3 000 строк демона (иконка в строке меню,
повторное отключение после сна, восстановление зависшего внешнего монитора). blackpane —
одна программа примерно на 650 строк вместе с комментариями, без меню и настроек. Код
написан с нуля; публичные материалы этих проектов помогали разбирать проблемы по ходу
работы.
